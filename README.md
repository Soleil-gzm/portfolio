# Dialogue Repair Agent｜LLM Agent 工程作品集

这个作品集的主体是我独立设计并实现的对话质量 Agent，以及支撑它的对话数据生产链路。Agent 负责检测模板拼接对话中的跨轮语义问题，并在约束下处置问题样本；数据生成与清洗工程提供了它要处理的数据场景和质量问题来源。

- **在线作品集**：https://soleil-gzm.github.io/portfolio/
- **Agent 源码**：https://github.com/Soleil-gzm/dialogue-repair-agent

## 主项目：Dialogue Repair Agent

模板拼接对话在局部是通顺的，但模块切换处容易出现答非所问、指代断裂、角色混淆等问题。直接对全量数据调用 LLM 改写既昂贵，又会改动金额、编号、日期等关键内容，而且无法证明改写没有破坏原文。

因此我把 Agent 的设计目标定为：先检测需要处理的轮次，再对问题局部做受约束的改写，同时保留原文回退路径。运行时由 LLM 选择工具，参数由运行时注入；所有处置都要通过保真校验，违规即回退原文。

**当前已完成语义检测、原文回退与受限改写；改写必须通过复检，修复率仍偏低。**

| 组成 | 实现 |
| --- | --- |
| 工具 | `check_consistency`（R1–R5 保真校验）、`check_coherence`（C0–C3 连贯性检查）、`fallback_keep`（回退原文）、`rewrite_segment`（受限局部改写） |
| 决策 | 规则策略与 LLM function calling 双策略；模型只选择工具名，参数由运行时注入 |
| 可靠性 | 迭代 / 调用 / token / 墙钟预算，重复工具调用识别，checkpoint 断点续跑，Trace；cassette 录制后可离线回放 |
| 成本 | append-only token 账本，记录缓存命中、价格表版本与折算成本；本地推理另记参考成本 |
| 评测 | 四元组基线指纹、不可变 `baseline_lock.json`、六臂单变量对照与自动报告；胜率 Wilson CI + 精确 McNemar；长度比 / distinct-2 / 跨样本 4-gram 退化指标；replay 档零成本复核 |
| 数据 | 公开轨 `v1` 冻结；`realistic` 档用私有轨聚合分布校准轮次、重复率、长度与实体密度 |

### 评测结果

评测集包含 120 条程序化合成缺陷和 12 条干净样本，缺陷覆盖答非所问、指代断裂、事实冲突、角色混淆、重复空转和缺失承接六类。本轮生成与判官均为本地 Ollama `qwen3:8b`（`Q4_K_M`，8.2B），现金支出为 ¥0；表中的 ¥ 是按 DeepSeek `deepseek-flash` 2026-11 高峰价折算的**参考成本**，不是真实账单。

| 指标 | 结果 |
| --- | --- |
| 公开 Agent 仓库测试 | 531 passed / 1 skipped |
| 公开轨分布校准 | `realistic` 1000 条：轮次中位 11、assistant/user 唯一率 49.3% / 28.3%、system 363–365 字；只匹配私有轨聚合分布，不复制原文 |
| A2：单次 LLM 重写 | 宏观阻断率 0%（无回退），干净样本改写 10/12，参考成本 ¥0.93 |
| A3：规则决策 + 确定性工具 | 宏观阻断率 83.3%，0 token，¥0 |
| A3L：LLM 决策 + 确定性工具 | 宏观阻断率 83.3%，233,376 tokens，参考成本 ¥0.87 |
| A3R：规则 + 受限改写 | 宏观阻断率 63.3%，修复 24 条，参考成本 ¥0.21 |
| A4：LLM + 确定性工具 + 语义判官 | 宏观阻断率 98.3%（D1 18/20），273,798 tokens，参考成本 ¥1.06 |
| A4R：LLM + 全工具集 | 宏观阻断率 84.2%，修复 16 条（13.3%），参考成本 ¥1.42 |
| 干净样本误报 | A2 为 10/12；其余五个臂均为 0/12 |

修复成功的样本计入 `repaired` 而不是回退，因此 A3R / A4R 的 `blocked` 低于只回退的臂，这不是退化；`repaired` 尚未人工抽检，不能当作语义正确的证明。以上结果来自当前合成评测集上的单次运行，用于比较不同策略，不直接外推到真实生产场景。

## 数据链路项目

Agent 处理的数据来自下面两个项目。它们的工程问题也解释了为什么需要语义层检测：规则能管住结构和实体，却管不住跨轮语义。

### 可控多轮对话生成引擎

针对人工编写难以覆盖复杂场景组合的问题，我负责生成引擎的架构设计与主要实现，根据条件组合和模块路径生产可控的合成训练数据。

[查看项目案例](https://soleil-gzm.github.io/portfolio/cases/generator/)

### 对话数据清洗与语义增强流水线

针对合成数据过于规整、缺乏真实电话对话特征的问题，我负责流水线的重构与主要实现，通过清洗与语义增强补充结巴、重复和口音相关转写差异，提升训练数据的多样性。

[查看项目案例](https://soleil-gzm.github.io/portfolio/cases/pipeline/)
