# Before / After 对照

数据为**程序化合成**（中立域：订单售后回访），不含任何真实业务信息。
对照的口径：**受损候选 → Agent 输出**。当前 Agent 不重写，输出只可能是原文或候选本身。

## 案例：答非所问（D1）

原始对话的第 2 轮：

```
user      : 已经等很久了，麻烦帮我催一下。（订单号 ORD-556516）
assistant : 我已为您催办，预计两个工作日内有进展。
```

注入缺陷后（换成跨话题回复）：

```
user      : 已经等很久了，麻烦帮我催一下。（订单号 ORD-556516）
assistant : 请在十五分钟内完成支付，否则订单会自动关闭。
```

Agent 决策链（`04_trace_sample.jsonl`，A4 档位，live）：

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | `check_consistency` | 通过（system / 结构 / 实体 / 说话人 均未变） |
| 2 | `check_coherence` | 违规：`C3_off_topic @turn 2` —— "用户催单，却回复要求支付" |
| 3 | `fallback_keep` | 回退原文，流程终止 |

输出：

```
assistant : 我已为您催办，预计两个工作日内有进展。
```

为什么这条必须靠语义判官：字面规则对 D1 的命中是 **0/20** —— 替换后的句子结构完整、
没有新增实体、也没有复读用户内容，四项硬约束全部通过。只有"这句话在回应什么"能发现问题。

## 各类型缺陷由谁拦住（实测）

| 缺陷 | 拦截手段 | A3（规则） | A4（含判官） |
|---|---|---|---|
| D1 答非所问 | 语义判官 | 0/20 | 20/20 |
| D2 指代断裂 | 实体保真（R3） | 20/20 | 20/20 |
| D3 事实冲突 | 实体保真（R3） | 20/20 | 20/20 |
| D4 角色混淆 | 跨角色泄漏（R5） | 20/20 | 20/20 |
| D5 重复空转 | 相邻轮相似度（C1） | 20/20 | 20/20 |
| D6 缺失承接 | 结构不变（R2） | 20/20 | 20/20 |

## 失败时怎么办

Agent 的默认动作是**保住数据**而不是"尽力修一版"：

- 任一校验报出违规 → `fallback_keep` 回退原文
- 判官不可用（网络/解析失败）→ 记为 `C0_judge_error`，同样回退，不静默放行
- 预算或墙钟触顶 → 终止并标记 `stopped`，不产出未经验证的版本

这也是当前阶段的取舍：**先保证"不会改坏"，再谈"改得更好"**。
重写工具只留了接口，接入后本文件会增加"候选 → 重写 → 校验通过"的第三个版本。
