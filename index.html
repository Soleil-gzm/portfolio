LLM Agent · Runtime & Evaluation

Dialogue Repair Agent

ReAct 决策循环 · 工具契约 · 服务化与可评测

在数据生产阶段，我负责可控多轮对话生成引擎的架构设计与主要实现， 根据条件组合和模块路径生成合成训练数据，解决人工编写难以覆盖复杂场景组合的问题。

在数据清洗与增强阶段，我负责流水线的重构与主要实现。当时的目标是解决合成数据 过于规整、缺乏真实电话对话特征的问题，补充结巴、重复以及口音导致的转写差异等变化， 提升训练数据的多样性，为模型训练提供更接近真实场景的样本。

我在前两个项目中发现，规则流程能够处理结构和实体问题，却难以覆盖模块切换处的 答非所问与衔接生硬；全量调用 LLM 改写又会增加成本，并引入内容保真风险。 因此，我把它做成一个带工具契约的 Agent 运行时：模型在 ReAct 循环里只选择工具， 参数由运行时注入；默认逐轮检查，长对话可切到 Planning&Executor 先选候选轮再精查。 运行时提供四维预算、Trace、checkpoint 与 cassette 回放，并已通过 FastAPI 与 Docker Compose 服务化；评测用六臂单变量消融，证明每个设计选择的净收益。

可控生成

针对人工编写对话效率低、难以随业务需求变化快速切换场景的问题，用概率矩阵、条件解析和特殊场景模块处理策略生成可控样本。

清洗与增强

针对生成的数据有语义重复、分布不均、缺真实噪声的问题，采用可插拔流水线做结构治理和鲁棒性增强。

Agent 质量闭环

规则可以控制单一场景的对话合成，但是跨轮语义和模块间跳转衔接的对话依旧会存在语义不连贯的问题。用受约束的工具循环检测、改写处理，并保证内容符合逻辑。

项目说明

Agent 项目由我独立设计并持续完善，当前已完成ReAct 决策循环、Planning&Executor、 工具契约与预算护栏、FastAPI + Docker 服务化、Ollama 检索增强，以及六臂单变量消融。 改写必须通过保真与连贯性复检，未通过则回退原文，修复率仍偏低。
